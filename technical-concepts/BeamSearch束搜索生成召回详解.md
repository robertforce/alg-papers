# Beam Search：束搜索在生成式召回中的工作原理与具体过程

## 1. 问题设定：为什么生成式召回需要搜索？

判别式召回对固定候选集打分排序；生成式召回没有预先给定的候选集，而是**自回归地生成物品标识符**，候选集是生成的副产品。

以 [OneTrans-V2 原文](../../OneTransV2.2609.28589v1.pdf)（§4.2.1、§5.2）的设定为例：

- 每个物品用三级语义标识符 \((SID_0,SID_1,SID_2)\) 表示，由多模态 embedding 经 RQ-KMeans 得到；
- 每层码本 8192 个条目；
- 生成顺序为：决策前缀（两个 token 位置）→ \(SID_0\) → \(SID_1\) → \(SID_2\)。

于是所有可生成的物品构成一棵编码树：

```text
决策前缀 z
   └── SID0（8192 选 1）
          └── SID1（8192 选 1）
                 └── SID2（8192 选 1）
                        → 一个完整 SID → 映射到一个或多个物品
```

检索就是在这棵树上找高概率路径。三种策略：

| 策略 | 做法 | 问题 |
|---|---|---|
| 穷举 | 枚举全部路径 | \(8192^3\approx5.5\times10^{11}\) 条，不可行 |
| 贪心解码 | 每步只保留当前最优的 1 条路径 | 早期局部最优可能锁死全局更优路径 |
| **束搜索** | 每步保留分数最高的 \(k\) 条路径 | 近似搜索；\(k\) 越大越接近穷举 |

## 2. Beam search 的通用原理

### 2.1 路径分数

模型给出链式分解的条件概率，一条完整路径的分数是各步对数概率之和：

$$
\text{score}(\text{path})
=\sum_{t}\log P(\text{token}_t\mid \text{context},\text{token}_{<t})
$$

用对数求和而非概率连乘，既避免数值下溢，又保持单调性：连乘越大，对数和越大。

### 2.2 逐步扩展与剪枝

```text
维护一个大小为 k 的候选路径集合（beam）

重复直到生成完整路径：
    1. 对集合中每条路径，计算下一步所有词表取值的分数（扩展）
    2. 在所有"旧路径 × 词表"组合中，保留累计分数最高的 k 条（剪枝）
    3. 用这 k 条替换旧集合

结束时：集合中的 k 条完整路径按分数排序输出
```

束搜索是**确定性的**：给定模型分数，输出固定，不做随机采样。

### 2.3 贪心为什么不够

贪心解码等价于 \(k=1\) 的束搜索。它每步取局部最优，但当前最优 token 的后续子树可能整体平庸，而当前略差的 token 后面接一个非常尖锐的子树。第 4 节的数值例子会具体展示这种失败。

同时注意：束搜索也不保证找到全局最优路径。真实最优路径若早期分数平庸，可能在某一步被剪掉。\(k\) 增大只是让这种失败更罕见，并增加计算。

## 3. OneTrans-V2 中生成召回的完整流程

结合决策条件生成召回（DCGR），一次请求的召回生成分为五步。

### 第一步：编码共享用户上下文

行为序列 \(S\) 加上召回上下文 token CTX 组成 \(H=(S,CTX)\)，由共享因果 Transformer 编码并**缓存**。后续所有决策评分和束扩展都读取这份缓存，不再重复编码历史。

### 第二步：决策前缀枚举评分（一次前向）

四个决策维度 \((z_{oc},z_{disc},z_{ad},z_{aov})\) 的词表都很小，合法组合数量有限。因此**不逐步解码**，而是枚举全部合法组合 \(z\)，在缓存上下文上一次前向算出：

$$
\log P(\mathbf z\mid H)
$$

（非法组合在评分前被排除，例如未购买时消费档位 \(z_{aov}\) 的部分取值；论文只说"每个合法组合"，具体过滤规则未披露。）

### 第三步：加业务偏置

每个决策前缀的分数加上偏置项：

$$
\log P(\mathbf z\mid H)+\beta\phi(\mathbf z)
$$

\(\phi\) 给目标维度的每个取值分配偏置，标量 \(\beta\) 控制整体强度，可在线调整。**偏置只加在决策项上**：给定某个决策 \(z\)，SID 的生成模型 \(P(Item\mid H,z)\) 不变，改变的只是哪些决策前缀能进入并留在 beam 里。

### 第四步：SID 逐级束扩展

从存活的决策前缀出发，对 SID 树做 3 步串行束搜索。每一步联合排序"前缀 + 已生成的 SID 编码"，即论文式（4）：

$$
\underbrace{\log P(\mathbf z\mid H)+\beta\phi(\mathbf z)}_{\text{引导后的决策前缀}}
+\sum_{\ell=0}^{2}\log P(SID_\ell\mid H,\mathbf z,SID_{<\ell})
$$

每步扩展 \(k\) 条路径 × 每路径 8192 个候选码，保留累计分数最高的 \(k\) 条。注意：

- 同一个决策前缀可以分叉出多条 SID 路径；
- 不同决策前缀共同竞争同一批 beam 名额；
- 决策分数高不保证胜出——还要看它能否延伸出高概率的 SID 路径。

### 第五步：SID 映射为物品，返回 top-K

搜索结束时得到 \(k\) 条完整路径（决策前缀 + 三级 SID）。把每个 SID 映射回物品：**多个物品可能共享同一 SID，命中该 SID 的所有物品都返回**。最终交给粗排的是 \(K\) 个物品，\(K\) 是物品数，与束宽 \(k\) 是两个不同的量。

## 4. 完整数值例子

以下数字全部为教学示例。真实系统每层码本 8192，这里缩为 4 个码 \(\{0,1,2,3\}\)；束宽 \(k=2\)。所有分数已用脚本逐项验证。

### 决策前缀阶段

枚举出 4 个组合（示例），其中 \(z_2\) 含"广告"取值：

| 组合 | \(\log P(z\mid H)\) | 业务偏置 \(\beta\phi\) | 引导后分数 |
|---|---:|---:|---:|
| \(z_1\)（自然供给） | −0.5 | 0 | −0.5 |
| \(z_2\)（广告供给） | −0.9 | +0.8 | **−0.1** |
| \(z_3\) | −1.6 | 0 | −1.6 |
| \(z_4\) | −2.8 | 0 | −2.8 |

束宽 2，保留 \(z_2\)（−0.1）和 \(z_1\)（−0.5）。注意偏置的作用：没有偏置时 \(z_2\)（−0.9）落后于 \(z_1\)（−0.5）；加了 +0.8 后反超。若 \(k=1\)，偏置直接决定哪条路径进入 SID 阶段。

### SID 第 0 级：8 个候选，保留 2 个

每条存活前缀向 4 个码扩展，累计分数 = 前缀分 + \(\log P(SID_0\mid H,z)\)：

| 路径 | 本步分数 | 累计分数 |
|---|---:|---:|
| \(z_2\to 3\) | −0.15 | **−0.25** ✓ |
| \(z_2\to 0\) | −0.5 | **−0.6** ✓ |
| \(z_1\to 0\) | −0.3 | −0.8 ✗ |
| \(z_1\to 1\) | −1.2 | −1.7 ✗ |
| \(z_2\to 1\) | −2.0 | −2.1 ✗ |
| \(z_2\to 2\) | −2.8 | −2.9 ✗ |
| \(z_1\to 2\) | −2.5 | −3.0 ✗ |
| \(z_1\to 3\) | −3.0 | −3.5 ✗ |

保留 \(z_2\to3\)、\(z_2\to0\)。\(z_1\) 的所有分支被剪掉——束宽有限时，弱势前缀可能整支出局。

### SID 第 1 级：8 个候选，保留 2 个

| 路径 | 本步分数 | 累计分数 |
|---|---:|---:|
| \(z_2\to0\to2\) | −0.05 | **−0.65** ✓ |
| \(z_2\to3\to2\) | −0.5 | **−0.75** ✓ |
| 其余 6 条 | ≤ −2.25 | ✗ |

### SID 第 2 级：得到最终 2 条完整路径

| 完整路径 | 本步分数 | 最终分数 |
|---|---:|---:|
| \(z_2\to0\to2\to0\) | −0.45 | **−1.10** |
| \(z_2\to3\to2\to0\) | −0.5 | **−1.25** |

### 贪心解码的对照

\(k=1\)（贪心）的轨迹：

```text
选前缀 z2（-0.1，引导后最优）
→ SID0 选 3（累计 -0.25，当前最优）
→ SID1 选 2（累计 -0.75）
→ SID2 选 0（最终 -1.25）
```

贪心只返回 1 条路径，分数 −1.25。而束搜索 \(k=2\) 的最优路径 \(z_2\to0\to2\to0\)（−1.10）在第 0 级时（−0.6）**劣于**贪心所选的 \(z_2\to3\)（−0.25），却被保留下来并最终胜出。这就是"局部最优 ≠ 全局最优"的具体形态。

反过来也要诚实：这条 −1.10 的路径在第 0 级只比被剪掉的 \(z_1\to0\)（−0.8）高 0.2。若 \(k=2\) 时它恰好排第三，真全局最优就会被剪掉——束搜索是近似，不承诺最优。

### 两阶段 top-k：先组内后全局

第 0 级的全局比较要在 \(k\times V=2\times4=8\) 个候选里选。论文（§5.2）将其替换为两阶段：

```text
第一阶段：每条 beam 内部保留自己的前 k 个扩展
    z1 → {z1→0 (-0.8), z1→1 (-1.7)}
    z2 → {z2→3 (-0.25), z2→0 (-0.6)}

第二阶段：在这 k×k=4 个候选里选全局前 k
    → {z2→3, z2→0}   与全局 8 选 2 结果完全一致
```

原因是确定性的：若某条路径进入全局前 \(k\)，它必然是所属 beam 的前 \(k\) 名之一（否则该 beam 至少有 \(k\) 条路径排在它前面，全局前 \(k\) 已满）。所以两阶段筛选**精确等价**，而中间池从 \(k\times V\)（如 2×8192=16384）缩到 \(k\times k\)（如 4）。

论文 §7.9 报告该优化在其线上延迟预算下把解码吞吐提升 19.7 倍、单请求束搜索延迟降低 2.3 倍，再加决策前缀单步评分后合计 27.6 倍。注意这是相对其自有未优化实现的对比，吞吐倍数高于单请求延迟倍数（吞吐在延迟约束下按最大 batch 测量），不能当作相对旧生产系统的端到端倍数。

## 5. SID 映射物品与返回预算

```text
最终 beam（k=2 条完整路径）：
    (z2, 0, 2, 0) 分数 -1.10 → 映射物品 {item_a, item_b}
    (z2, 3, 2, 0) 分数 -1.25 → 映射物品 {item_c}

返回给粗排：K = 3 个物品
```

三个量必须区分：

- \(k\)：束宽，搜索过程中保留的路径数；
- 最终 SID 数：通常等于 \(k\)，但不同路径可能落在同一 SID；
- \(K\)：返回物品数，因 SID 冲突（多物品共享 SID）而可能大于 SID 数。

论文没有披露真实线上的 \(k\) 和 \(K\)，也没有说明：同一 SID 被多条决策路径命中时分数如何聚合、物品如何去重和截断、SID 冲突导致数量波动时如何控预算。这些属于未披露细节，不能凭常识补全。

## 6. 效率特征：为什么束搜索在这里是可负担的

- **历史只编码一次。**所有 beam 读取同一份缓存 \(H\) 的 K/V，昂贵的长序列编码不随 beam 数增长。
- **beams 可以批量。**\(k\) 条路径的每步解码可组成一个 batch，一次前向算出各路径的下一码分布。
- **每步成本是 \(k\times V\) 规模的打分加 top-k。**两阶段 top-k 把中间池从 \(k\times V\) 压到 \(k\times k\)，V=8192 时节省显著。
- **串行深度固定。**2 个决策位置可并成一次评分（枚举），SID 只有 3 步，总串行步数少。

与 [GQA](./GQA分组查询注意力详解.md) 和 [FlashAttention](./FlashAttention高效注意力计算详解.md) 的关系：GQA 缩小这份被所有 beam 共享读取的历史 K/V 缓存；FlashAttention 风格算子优化 beam 与历史之间的注意力读取。三者作用在不同层面，可叠加。

## 7. 常见误解

1. **"Beam search 返回 k 个不同物品。"**返回的是 k 条路径；SID 冲突可能让物品数大于、等于或小于 k。
2. **"束宽越大结果一定越好。"**近似质量单调改善，但收益递减、计算线性增长，且大束宽可能挤占路径多样性。
3. **"束搜索保证找到概率最高的物品。"**不保证；剪枝可能丢弃真最优路径，穷举才精确。
4. **"业务偏置改变了物品生成模型。"**偏置只改决策前缀的排序，给定决策的 SID 生成分布不变。
5. **"决策分数最高的前缀一定会产出最终物品。"**前缀携带分数进入联合搜索，可能被延伸出高概率 SID 的其他前缀超越。
6. **"Beam search 是采样。"**给定分数它是确定性的；引入随机性属于额外设计。
7. **"每步都要重新编码用户历史。"**历史 K/V 缓存一次，所有步、所有 beam 复用。

## 总结

**生成式召回的 beam search 是在"决策前缀 + 三级 SID"编码树上的近似最优路径搜索：先在缓存上下文上一次前向枚举评分决策组合并加业务偏置，再从存活前缀出发逐级扩展、按累计对数概率保留前 k 条路径，最终把胜出 SID 映射为物品集合返回给粗排。它用有限的 \(k\) 条并行路径逼近不可穷举的大树，局部最优陷阱靠多路径冗余化解，计算靠共享缓存和两阶段 top-k 控制在预算内。**
